## TL;DR

Login is scoped as email + password authentication only (per Tester Refinement Instruction — no Apple Pay or social login at the authentication step). The shopper persona is a mobile-first iOS Safari user, so compatibility and interaction capability on that platform matter, but the authentication mechanism itself is a standard credential-based login.
**Test risk level:** High

## Test Approach Decision

| Test Type | Decision | Rationale |
|-----------|----------|-----------|
| Functional | Yes | Core credential validation (valid/invalid email-password combinations, error messaging) must be verified against the test basis — this is the primary purpose of the login feature. |
| Regression | Yes | Login is a high-traffic entry point touched by many other features (checkout, account, order tracking); a regression suite protects against defect reintroduction across releases. |
| Integration | Yes | Login typically calls an authentication API/service; integration tests confirm the UI and backend contract (status codes, token issuance) behave consistently. |
| Performance | No | Performance/load/stress testing is out of scope for this discipline; response-time risk is flagged in the Impact Radar as a risk to monitor, not tested here. |
| Security | Yes | Authentication is the single highest-value attack surface in this artifact (brute force, credential stuffing, injection, token exposure) — zero security coverage would fail the mandatory security gate. |

## Top 3 Test Focus Areas

1. **Authentication & brute-force protection** — Verify valid/invalid/expired credential handling and account lockout behavior; this is the largest functional and security risk since login is the sole gatekeeper to account and order data.
2. **Input validation & injection resistance on email/password fields** — Boundary lengths, special characters, and SQL/script injection patterns must be tested since these are the only user-controlled inputs on this screen.
3. **Session token handling post-login** — Confirm token issuance, expiry, and logout invalidation to ensure no stale or leaked session data persists into checkout or account pages.
